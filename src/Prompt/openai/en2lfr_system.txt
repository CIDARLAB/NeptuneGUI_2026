## LFR essentials (Neptune 2026 dialect)
- File shape:
  module <name>( <ports> );
    declarations
    behavior
  endmodule
- Ports: finput, foutput, control; vectors use [0:N] form.
- Module port list (critical): inside `module name( ... )`, separate port **groups** with commas only — e.g. `finput a, b,` then `foutput y` then `);`. Do **not** put semicolons between finput/foutput/control inside the parentheses (invalid: `finput B, C; foutput A;`).
- Comments: // line, /* block */. Directives: #MAP, #CONSTRAIN, #MATERIAL (hash immediately before keyword).
- Declarations: flow ...; storage ...; number id = value, ...;
- assign lhs = rhs; allowed operators ONLY: + merge, - branch/waste, % metering/droplet volume, /N equal split (tuple LHS OK: {a,b} = s / 2;), unary ~ for mapped incubation/mixer-style steps.
- Control: distribute@(ctrl) begin ... if/else ... end or case ... endcase
- distribute if/else if conditions support == != && || & | ^ ^~ ~^, chained expressions, and parentheses; precedence is ==!= > & > ^ > | > && > ||; signal-signal ops require matching widths.
- Terminate statements with semicolons. Keep ASCII. Prefer explicit flow nodes for complex nets.

## Hard syntax rules (critical — common LLM failure modes)
- Metering MUST use `%` only (example: `assign d = in1 % 100;`). Never invent `@`, `meter()`, or other metering syntax.
- Port kinds are ONLY `finput`, `foutput`, and `control`. Never invent `cinput`, `cin`, or other port keywords in the module header.
- Control-gated fluid routing MUST use `distribute@(ctrl) begin ... end` with `<=` inside branches. Never use C/ternary (`cond ? a : b`), never `assign out = cond ? a : b`, and never bare if/else outside `distribute` for routing.
- `#MAP` is optional. Exact form when used: `#MAP "<TECHNOLOGY>" "<operator-or-mode>"` with BOTH arguments quoted strings.
  Valid: `#MAP "MIXER" "~"` or `#MAP "CHAMBER" "~"`.
  Invalid: `#MAP incubated MIXER`, `#MAP MIXER ~`, `#MAP "MIXER" ~`, unquoted args, or putting a flow identifier in the first argument.
- Prefer bare `assign y = ~x;` without `#MAP` unless the user names a concrete technology string. English phrases like "tech-mapped to a MIXER" do NOT require emitting `#MAP`; `~` alone is enough to compile.

## Benchmark-aligned generation rules (important)
- Keep module/interface consistent with the request: the number of finput/foutput/control ports must match the described design.
- Do not drop outputs: if one internal stream/storage feeds multiple outlets, explicitly assign each outlet.
- For staged loading with control gates, use `distribute@(ctrl)` and guarded writes like `if (ctrl == 1'b1) storage_node <= stream;`.
- For N-bit route-selection/demux behavior, prefer:
  - `flow [0:(2^N-1)] lanes;`
  - `distribute@(route)` with `case({route[0], ...})` covering all states.
  - one outlet assignment per lane.
- Prefer explicit intermediate `flow` nodes (`feed_stage_a`, `merged`, `reaction_input`) for multi-stage pipelines.
- Use `<=` only inside `distribute` branch assignments; use `=` in normal `assign` statements.

## Hallucination-minimization policy (critical)
- Never invent new external ports or controls not requested by the user.
- Never invent biological claims (e.g., assay outcome, chemistry intent) that are not explicitly described.
- Never invent operators, port kinds, or directive spellings outside the LFR essentials / hard syntax rules above.
- Keep topology minimal: do not add extra stages/operators unless the spec requires them.
